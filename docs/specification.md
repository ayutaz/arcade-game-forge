# 初版の仕様と検証範囲

対象はmaze/dodge/collectの3種。`examples/specs/`を入力例とする。
全キー必須、未知キーとboolの数値利用を拒否。IDはジャンルに対応する専用`forge-*`だけ。
到達不能な目的地、重複/範囲外の座標、開始位置への壁、成立しない回避時間を事前に拒否する。

| 項目 | 契約 |
|---|---|
| 操作 | Aで開始、方向は押下edge、Bで表紙へreset、FN+B/BACKで終了 |
| 状態 | 表紙0/実行1/勝利2/敗北3。終了は他処理より優先 |
| 時計 | dt 0〜60000ms。開始/resetのframeでは加算せず、勝敗後は停止 |
| 迷路 | 壁/外周への移動を拒否、goalで得点1と勝利 |
| 収集 | 各coinは1回のみ得点、全回収で勝利 |
| 回避 | 固定32bit LCGの単独落下物、非衝突通過で得点、接触で敗北 |
| 描画 | 320×240、RGB565。固定位置/色のplayer・wall・goal/coin/hazard・状態・得点bar |
| guest | drawのみ、2pages/128KiB、50000fuel/呼出し、128rect/呼出し、package16KiB |

生成器に渡す完全なAPI/時間順序/描画契約は`prompts/game-contract.txt`。
Pythonの独立Game oracleと評価用入力列は生成promptへ含めない。
失敗後には最初の不一致の状態等を渡し、未提示の全入力列を漏らさない。
修正後も同じ契約を使い、生成結果に合わせて評価器を緩めない。

## 合格条件

1. 限定C profile、固定SDKでコンパイル、package上限/権限を通過。
2. 勝利経路、edge/複合入力、reset、期限、大きなdt、乱数入力、終了を検証。
3. Wasmtime/WAMRの状態と描画が一致し、両方とも独立oracleと一致。
4. player等の必須矩形が存在し、上書きで消されず、範囲/個数制限を満たす。
5. 終了後のVMがclosedとなり、同じCから再buildしたpackage hashが一致。

これでも面白さ、任意の未試験入力、ESP32-S3速度、実LCD/実キーは保証しない。
3仕様の生成成功を一般的なAI成功率や任意ゲーム生成へ拡大しない。
既存の手書きfixtureのbuild成功は、AIによる新規生成成功とは別に記録する。
